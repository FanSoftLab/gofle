# Основи пошуку

> **Тип контенту**: Task — пошук контенту логу використовуючи primary query, regex, case sensitivity, та invert match.
> **Аудиторія**: Усі користувачі
> **Передумови**: [Відкрити файли](open-files.md) або [Відкрити віддалено](open-remote-ssh.md) — файл завантажений у вкладці
> **Verified**: 2026-10-29 — протестовано з локальними та віддаленими файлами

## Призначення

Знайти рядки, що відповідають патерну, в поточно відкритому лог файлі, використовуючи панель інструментів пошуку.

## Передумови

- Лог файл відкритий у активній вкладці
- Панель інструментів пошуку видима (за замовчуванням)

## Процедура

### 1. Фокус на полі пошуку

- Натисніть `/` (slash) — фокусує primary поле пошуку
- Або клацніть на primary поле пошуку (ліве поле)

### 2. Введіть Primary Query

Введіть ваш пошуковий патерн:

- **Plain text** (за замовчуванням): відповідає підрядку будь-де в рядку
- **Regular expression**: увімкніть Regex toggle (див. крок 3)

Приклади:
```
ERROR
timeout
request-id-12345
Failed to connect
```

### 3. Налаштуйте опції пошуку

| Опція | Скорочення | Опис |
|-------|------------|------|
| **Match Case** | `Alt+C` | Case-sensitive пошук (за замовчуванням: вимкнено) |
| **Regex** | `Alt+R` | Інтерпретувати запит як RE2/Go regex (за замовчуванням: вимкнено) |
| **Invert Match** | `Alt+I` | Показати рядки, що НЕ відповідають (за замовчуванням: вимкнено) |

Натисніть кнопки перемикання або використовуйте клавіатурні скорочення.

### 4. Виконайте пошук

- Натисніть `Enter` в полі пошуку, АБО
- Натисніть іконку пошуку (лупа), АБО
- Пошук запускається автоматично після короткого debounce

### 5. Перегляньте результати

- Результати з'являються в **панелі результатів** (нижня панель за замовчуванням)
- Кожен результат показує: номер рядка, контент рядка, що відповідає
- Клацніть на результат, щоб перейти до цього рядка в повному логу (верхня панель)
- Лічильник показує: "X matches of Y lines"

### 6. Навігація по збігах

| Дія | Скорочення | Кнопка |
|-----|------------|--------|
| Next match | `F3` / `Alt+↓` | ↓ |
| Previous match | `Shift+F3` / `Alt+↑` | ↑ |
| First match | `Alt+Home` | ⇈ |
| Last match | `Alt+End` | ⇊ |

### 7. Використання AND поля (Secondary Filter)

- Введіть текст в **AND поле** (праве поле, позначене "AND")
- І primary, І secondary повинні відповідати в тому ж рядку
- Логіка: AND (за замовчуванням) або OR (перемикання через dropdown)

Приклад:
```
Primary: ERROR
AND: database
→ Рядки, що містЯть І "ERROR" І "database"
```

### 8. Очистити пошук

- Натисніть `Esc` в полі пошуку, АБО
- Натисніть **×** (очистити) кнопку поруч з полем пошуку
- Обидва primary та AND поля очищаються

## Очікуваний результат

- Панель результатів заповнюється рядками, що відповідають
- Збігаючі терміни підсвічуються в обох панелях (налаштовується)
- Номери рядків показані в результатах
- Панель повного логу переходить до рядка вибраного результату

## Перевірка

1. Відкрийте файл з відомим контентом (наприклад, `/var/log/syslog`)
2. Пошук `ERROR` — підтвердьте, що рядки ERROR з'являються
3. Увімкніть **Match Case** — підтвердьте, що `error` більше не відповідає
4. Увімкніть **Regex** — пошук `ERROR|WARN` — підтвердьте, що обидва відповідають
5. Увімкніть **Invert** — підтвердьте, що показуються не-відповідаючі рядки
6. Використовуйте AND поле — підтвердьте, що обидві умови обов'язкові

## Деталі поведінки пошуку

| Аспект | Поведінка |
|--------|-----------|
| **Engine** | Паралельний worker pool (CPU cores) над line-offset індексом |
| **Індекс** | Тільки зміщення рядків в пам'яті; рядки читаються через `pread` на вимогу |
| **Regex** | RE2/Go синтаксис; невалідний regex підсвічується, пошук паузується |
| **Case** | Застосовується в engine, не post-filter |
| **Invert** | Застосовується в engine, не post-filter |
| **AND** | Refine pass над primary hits (коли змінюється тільки AND) |
| **Results** | Віртуалізовані — тільки видимі рядки в DOM |

## Вирішення проблем

| Симптом | Причина | Рішення |
|---------|---------|---------|
| Жодних результатів | Патерн відсутній у файлі | Перевірте правопис; спробуйте ширший патерн |
| Regex error (червоне поле) | Невалідний RE2 синтаксис | Виправте regex; ескейпніть спец. символи: `. * + ? ^ $ ( ) [ ] { } | \` |
| Пошук повільний на великому файлі | Перший пошук будує кеш | Наступні пошуки швидші (regex кешований) |
| Результати не переходять | Увімкнено Word Wrap | Вимкніть Word Wrap в Settings → Viewer |
| AND поле ігнорується | Primary порожній + advanced filters | Advanced filters застосовуються post-primary; AND все ще працює |
